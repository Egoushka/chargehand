# 0056. An operator console built with Vite and React, embedded in the server

- Status: accepted. Amends 0054: that ADR's "no build step, no third-party code" holds for `/ui/` only; the console at `/console/` has both.
- Date: 2026-10-13

## Context

ADR 0054 shipped a page of plain ES modules at `/ui/`: three screens in 845 lines, no types, and tests only for what a .NET test can see (served, headers, no external origin). The next screens (a fleet overview, run analytics with charts, a graph of a batch's tasks, highlighted code in claims, a command palette, tables with thousands of rows) are what libraries exist for, and every one of them assumes a build step. Writing them by hand as unbuilt modules would mean vendoring unaudited third-party files into `Ui/` with no compiler and no CI to check them, which is worse for supply-chain safety than a lockfile, not better. The owner chose a build step for this reason.

What stays from 0054: the repository is public, the page holds a bearer key that can start batches and halt the server for the owner, and run data is written by models and repositories, so it is untrusted text on a page that holds a key. The server must still build with `dotnet build` alone: the .NET tests and the `dnx` tool do not need Node.

## Options

### The stack

1. **Plain ES modules and vendored libraries** (0054, extended). No toolchain, but no types, no tests in CI, no tree-shaking, and vendored files that nobody builds from a lockfile.
2. **A server-rendered page** (Razor, Blazor, htmx). Live events and a tab-local key want client state anyway, and Blazor WebAssembly is a large runtime for a table. Rejected.
3. **A single-page app built with a bundler.** Framework: React, Svelte, Solid, Vue or Angular. The libraries the planned screens use (`@xyflow/react` for graphs, `cmdk` for the palette, Radix primitives, TanStack Table and Virtual) are React-first; uPlot, elkjs and Shiki are framework-free. React has the widest set of maintained parts and of people who can review the code.

### Where the build output goes

1. **A separate static site on another origin.** CORS and a second deployment; rejected in 0054 and still.
2. **Committed build output.** Generated files in review, stale on every merge.
3. **Built in CI and in the image, embedded in the server.** One artifact, same origin, nothing generated in the repository.

## Decision

- **React 19, TypeScript, Vite.** TanStack Router for typed routes and TanStack Query for the cache and polling; Table and Virtual join with the screens that need them. Radix primitives, uPlot, `@xyflow/react` with elkjs, Shiki and cmdk are not added now: each comes with its screen, its size named in that pull request. Tokens are CSS custom properties in plain CSS; a CSS-in-JS runtime would inject style at run time against `style-src 'self'`. Tests: Vitest with Testing Library for the API client, the stream parser and the screens; Playwright for one smoke test; Biome for lint and format (one tool, one config).
- **`web/console/`, embedded as resources, served at `/console/`.** `Chargehand.Server.csproj` embeds `web/console/dist/**` when `dist/index.html` exists. Without it the server still builds, and `/console/` answers `503` with a short page that says the console is not built, so `dotnet test` needs no Node. The Docker image builds the console in a Node stage and copies the files only; CI builds it before `dotnet build` so the .NET tests check what the server serves; the NuGet tool pack builds it first.
- **Same trust rules as 0054.** Files are public and need no key; `http.ui` gates both paths; the Host check applies; `/consolex` is not under `/console`. The key stays in `sessionStorage` and goes out as the bearer header, never a cookie. Events are read with `fetch`, because `EventSource` cannot send a header. Everything fetched is dropped from the query cache when the key goes, so a second sign-in never sees the first account's data. A link is built only from an `http` or `https` URL.
- **The policy is 0054's, unchanged:** `default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`, with `nosniff`, `no-referrer` and `X-Frame-Options: DENY`. The build is configured to fit it: nothing is inlined (`assetsInlineLimit: 0`), no source maps ship, `index.html` has no inline script or style. `scripts/verify-dist.mjs` runs after `vite build` and fails the build on an inline script or style, an event-handler attribute, a reference outside `/console/`, an unhashed asset or a source map. `vite preview` sends the same headers, so the smoke test fails on a violation (it listens for `securitypolicyviolation`, console errors and requests to another origin), and a .NET test checks that `web/console/csp.ts` holds the server's text.
- **Caching.** Files under `assets/` carry a content hash and are served `public, max-age=31536000, immutable`; `index.html` is `no-cache`. A path with no file extension that is not a file is a client route and gets `index.html`; a missing asset or any path with an extension is `404`, so a stale script is never answered with a page.
- **Supply chain.** The page holds the key, so a package that ends in the bundle runs with it, and the policy does not stop it calling this origin. So:
  - exact versions in `package.json`, `package-lock.json` committed, `npm ci --ignore-scripts` in CI, the Dockerfile and `scripts/check.sh`, and `ignore-scripts=true` in `.npmrc`: no package runs code at install;
  - nothing younger than 14 days: each direct pin was chosen that way, `min-release-age=14` in `.npmrc` holds it for every transitive package when the lockfile changes, and Dependabot's `cooldown` is 14 days;
  - Dependabot (npm, weekly, minor and patch grouped) proposes updates; a major version is its own pull request;
  - no CDN, no remote script, font or style; the Node base image in the Dockerfile is pinned by digest, and its version must equal `.nvmrc` (CI checks);
  - few direct dependencies (4 runtime packages at the foundation, 9 after the first amendment below, 10 after the second); each new one is argued in the pull request that adds it.
- **`/ui/` stays until the console reaches parity (reached and removed by 0072),** then goes with its `Ui/` folder and tests. Parity means: the runs list with its filters, a run with its live events, claims, tasks and artifacts, cancel, start a run or batch, learning, spend against caps, halt and resume. Until then `/ui/` takes bug fixes only. Both paths are behind `http.ui`.
- **Today's console is the foundation:** the router with a placeholder for each planned screen (overview, runs, run, needs you, new, analytics, learning, intake, repositories, accounts, system), a typed client for the routes that exist (`/v1/runs`, `/v1/runs/{id}`, `/v1/runs/{id}/events`, `/v1/accounts/me`, `/v1/learn`, halt and resume), sign-in, and the runs table. Types are written by hand from `schemas/`; generating them is a follow-up.

## Consequences

- The repository now has a JavaScript supply chain: 136 locked packages, of which 15 reach the bundle (React and ReactDOM, the two TanStack packages and their small cores); the rest run at build or test time only. A compromise of a bundled package is the risk this ADR accepts; the rules above shrink the window and the install-time reach, not the run-time one. Use an account key for everyday watching, as 0054 says.
- Node 24 (the active LTS) is a requirement of `scripts/check.sh`'s web steps, which it skips with a message when Node is absent, and of CI. Nothing in `dotnet build` or `dotnet test` needs it.
- CI gains a `web` job (lint, types, unit tests, build, smoke test) and Node steps in the `build` job. The image build gains a Node stage of well under a minute; the image grows by the size of the build (about 345 KB at the foundation).
- Bumping Node means `.nvmrc`, the Dockerfile tag and its digest together; the CI check catches one without the other.
- The server serves the build uncompressed. Over a private network that is acceptable (110 KB gzipped, 342 KB raw); compression is a later change if it is not.
- Two UIs exist for a while, with two sets of tests.

## Amendment, 2026-10-13: the design system, the shell, and the first two screens

The owner approved the console's visual design (a design system and 74 boards), and this change builds its foundation. What changes in the decisions above:

- **Radix and cmdk arrive** (the Decision said each comes with its screen, its size named in the pull request). Added, exact, each at least 14 days old when pinned: `@radix-ui/react-tabs` 1.1.21, `@radix-ui/react-dropdown-menu` 2.1.24, `@radix-ui/react-tooltip` 1.2.16, `@radix-ui/react-toast` 1.2.23 and `cmdk` 1.1.1 (the palette), plus `@axe-core/playwright` 4.13.0 for tests only. Runtime packages go from 4 to 9 and locked packages from 136 to 183. The bundle grows from 342 KB (110 KB gzipped) to 526 KB (167 KB gzipped) with the screens and the 77 icons; the stylesheet is 86 KB (14 KB gzipped). Radix is used only where the part is hard to get right and has to be accessible: tabs, a menu, a tooltip and toasts; cmdk does the palette's list, filter and keys. No other UI library and no CSS framework.
- **Modal layers are the browser's `<dialog>`, not Radix's.** Radix Dialog (and a modal Radix menu) lock the page's scroll by injecting a `<style>` element, which `style-src 'self'` refuses; the lock is lost and the browser reports a violation on every open. The native `<dialog>` opened with `showModal()` makes the page behind inert, traps focus, closes on Esc and returns focus, with no script and no style injected. The menu is Radix's non-modal one for the same reason. The smoke test fails on any policy violation, so this cannot come back unseen. Style is set through the style object model (custom properties such as `--p` and `--cols`), which the policy allows; an inline style attribute in markup would not be.
- **The design system's tokens are generated, not retyped.** `web/console/design/tokens.json` is a copy of the design system's token file (verbatim but for one sample string, a project name, made neutral) (133 colours in a dark and a light theme, type, spacing, radii, shadows, sizes, durations and layers). `scripts/gen-tokens.mjs` writes `src/styles/tokens.css` from it; `npm run build` and a unit test fail when the committed file is stale. Dark is the default theme; light is `data-theme="light"` or a browser that asks for it while no choice was made. `components/bundle.css` of the design system is committed verbatim (`src/styles/bundle.css`) and a test fails when it names a property that the tokens do not define or holds a literal colour. Fonts are the system's; nothing loads from another origin.
- **A person's choices stay in this browser.** Theme, row density, the rail's width and which notices to raise are kept in `localStorage` (not secret); the key stays in `sessionStorage` as before.
- **Browser notifications are an addition on a secure page.** The Notification API needs https or localhost. The console asks once, from a click, shows a notice on the page for each event, and raises a browser notification (same title) only while the page is in the background. On plain http it does nothing and says so.
- **Only what the server can do is offered.** The server has no route to merge a pull request, retry a task or answer except by starting a batch, so Needs you offers Open PR and Open run, and answers a question with the request the inbox item carries (`POST /v1/runs`, a driven task with `continue_from` and `answers`).

## Amendment, 2026-10-13: uPlot for the time series

Analytics draws spend, tokens and the cache-read share over time, in up to a few hundred buckets stacked by up to eight groups. That is the one place a chart library earns its size; every other chart (pass rate and its Wilson interval, budgets against p80 spend, the duration bins, the governor's rate per mode) is a few SVG elements and stays SVG.

- **Added: `uplot` 1.6.32** (exact; released March 2025, so far over the 14-day floor; MIT; no dependencies). It is 51 KB (22 KB gzipped) as a minified script and 1.9 KB of stylesheet; with the two screens the script grows by 104 KB (38 KB gzipped) and the stylesheet by 8 KB (2 KB gzipped). Runtime packages go from 9 to 10.
- **Why uPlot and not a larger library:** it draws on one canvas, it is small, and it writes no `<style>` element and no `style` attribute in markup (the plot's own sizes are set through the style object model), so `style-src 'self'` holds; its stylesheet is a file of this origin. The end-to-end tests fail on a policy violation and check that no style element exists. It has no tooltip or legend of the design system's, so the console draws both in HTML (and a table of the same numbers) and turns uPlot's own legend and cursor line off.
- **Colours stay tokens.** A canvas cannot use `var(--chart-1)`, so the console reads the token's computed value from the stylesheet whenever the theme changes and hands that to uPlot; a test fails when a chart or screen file holds a literal colour.
- **The dollar figure is an equivalent.** Spend on Analytics is `usd_estimate` (the tokens priced, also on a subscription), marked `≈`; a task that could not be priced is counted apart and never shown as zero.

## Amendment, 2026-10-13 (3): Runs, Batch run, Task and Research

The four screens that read runs arrive with the libraries the Decision named for them. Each is lazy where it is heavy, and each was checked against the policy by the end-to-end run, which serves the build with the server's headers and fails on a violation.

- **Four runtime packages**, exact, each at least 14 days old when pinned (the youngest is 18): `@tanstack/react-virtual` 3.14.13 (the Runs table draws the rows in view, not the 500 it may hold), `@xyflow/react` 12.12.0 (the task graph), `elkjs` 0.12.0 (its layout) and `shiki` 4.4.3 (syntax colour in a diff and in JSON). Runtime packages go from 9 to 13 and locked packages from 183 to 249. `elkjs` is licensed `EPL-2.0 OR GPL-3.0-or-later`; the console ships its worker file unmodified under the EPL-2.0 option.
- **The page's own script grows from 724 KB (231 KB gzipped) to 772 KB (248 KB gzipped)**, 48 KB of it the Runs screen and the router's search check. What loads only when a screen needs it: the batch, task and research screens (51 KB and 31 KB), the task graph with React Flow (180 KB, on the Tasks tab), Shiki's core and engine (112 KB and 58 KB, on the first diff or block of JSON) and one file per grammar (C#, TypeScript, JSON, Markdown, YAML and diff, 3 to 181 KB), and ELK's worker (1.6 MB, 464 KB gzipped, started by the graph). The router reads a batch's `tab` from a module of its own so none of that loads before a batch is opened.
- **Each library was made to fit `script-src 'self'; style-src 'self'`.** ELK runs in a Web Worker started from the worker file the build ships under `assets/` (a same-origin file is allowed; a worker built from a blob is not), and the graph falls back to a plain layering where there is no Worker. Shiki uses its JavaScript regular-expression engine (the default compiles WebAssembly, which the policy forbids) and its CSS-variables theme, so a token's colour is `var(--code-token-*)` from the design's tones and follows the dark and the light theme. React Flow's structural stylesheet is a file; it sets node positions through the style object model.
- **Task and batch data the server does not keep is said so.** Every tab that draws from `GET /v1/batches/{id}` shows the server's own `not_recorded` sentences that bear on it (events and sessions on the Timeline, governor decisions on the Governor tab, the transcript on a task, CI checks on the pull requests), and a request is shown as rebuilt, since the server keeps it in its run log and does not serve it. A clone starts from the rebuilt request: it travels in the router's history state to Start a batch and is in no address, no storage and no call.
- **A scrolling region is a tab stop.** A table, a log or a diff that scrolls sideways takes the focus, so the keyboard can scroll it (axe's `scrollable-region-focusable`).

## Reopen if

A package in the bundle is compromised, or the 14-day rule keeps blocking a security fix that matters; the console needs something the policy forbids; the bundle outgrows what an embedded, uncompressed file can reasonably serve; the page must be served from another origin or rendered on the server; or keys should come from an identity provider (0050, 0054).
