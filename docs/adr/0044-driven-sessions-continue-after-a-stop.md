# 0044. Driven sessions continue after a stop and keep their work

- Status: accepted
- Date: 2026-10-12

## Context

A driven session ([ADR 0039](0039-driven-writing-sessions.md)) is stopped by the driver after `max_turns` (80 in the `driven` preset) assistant messages, `max_minutes`, no progress or the token cap. Measured on the production box on 2026-10-12: large tasks hit the turn limit while still writing (one at 80 turns in the `write` stage) and the batch recorded `failed: the session was stopped: turn limit` with no result. The work was deleted. Three causes in the code:

1. `SessionDriver.BundleAsync` bundles `refs/heads/<branch>`, the commits the session made. A session stopped mid-write has uncommitted files, so the bundle holds nothing of them.
2. `TaskRunner` hands over (verify, push, draft pull request) only when the session completed and printed a report.
3. The task's `finally` block removes the container, the work volume and the scratch directory, so nothing survives a stop.

## Options

1. Raise `max_turns` for everyone. Costs every task, including the ones that finish in 20 turns, protects nothing at the new limit, and leaves the delete-on-stop behaviour.
2. Run the task again from scratch on a stop. Pays for the lost work twice and may stop at the same place.
3. Keep the work (commit the tree), carry on from it in a fresh session with its own turn budget, and hand over whatever exists when the continuations run out.

## Decision

Option 3.

- **Snapshot.** When the driver stops a session for any reason (a stall of any kind or the token cap), before it bundles it commits the working tree to the task branch: `git add -A`, then a commit `WIP: session stopped by <reason> after <n> turns`. The branch is created if the session never made it; a clean tree adds no commit; the repository's own git identity (set by the workspace helper) is used and hooks are off. Ignored files stay out, as in any commit; the workspace helper also excludes `/.dotnet/` and `/.nuget/`, where the session image keeps the .NET CLI home and the NuGet cache. Files over 5 MiB are unstaged before the commit and named in its message. Each git call of the snapshot has a timeout (3 minutes); a stale `.git/index.lock` (no git process is running) is removed, a live one skips the snapshot. A skipped snapshot, or files left out, is said in the outcome's `snapshot_note` and in the partial pull request's body. The handover scans every commit's patch (`git log -p base..branch`) and every path the history touched, not just the net diff, because the whole history is pushed. The outcome gains `commits`, the number of commits on the branch past the commit the workspace started at (recorded before the seed is applied; not "commits no remote has").
- **Continuation.** When a session ends `stalled` with reason `turn_limit` or `wall_clock`, its bundle holds at least one commit, fewer than `max_continuations` (new key of the profile's `driven.limits`, ADR 0039; default 2 in code when unset, 0 to 5; not in `presets/driven.yaml`, which Prompt CI gates) continuations have run and the task's token (and dollar) cap is not spent, `TaskRunner` starts another session for the same task: a new run id (container and volume names derive from it), the same branch name (`chargehand/<first run id>`), a workspace made as usual at the base commit, and the previous bundle written into the new output volume as `seed.bundle` (the runner may write it, up to 128 MiB). The driver fetches it into the workspace and resets the branch to it before it starts Claude Code. The prompt is the goal plus a note: continuation N of M, the stop reason and turns, "read `git log` and `git diff <base>..HEAD` first, do not redo finished work, finish the task, run the tests, and end with the same report block". Each continuation gets `max_turns` and `max_minutes` again. The token cap is the task's: each session is given what the earlier ones left. Usage in events and in the task's outcome is the sum. Each continuation publishes a `container_started` event (no new event kind). Earlier sessions' containers and work volumes are removed when the next one starts. The stop reasons that continue are one list, `StallDetector.ContinuableReasons` (`turn_limit`, `wall_clock`). A continuation has to add a commit past the one it was seeded with, or no further one starts. A continuation that cannot be started (the runner is full, the seed is refused, the call times out) does not cost the earlier work: the task goes on as if the previous session were the last. A no-progress stall, a repeated call, the token cap, a failed session and a question for a person (`needs_input`) never continue.
- **Salvage.** A task that ends without a completed report, with commits on its branch and no continuation left (or a stop that never continues), other than `needs_input`, is handed over as a **partial** draft pull request: title `[partial] <title>`, a body that says by what the session was stopped, after how many turns, and that the work is unfinished. The handover runs the verification and records it, but pushes and opens the draft even when the tests fail or time out or the repository has no test command (`HandoverInput.Partial`); a secret in the diff, CI-file changes and every other check still refuse. The task outcome stays `failed` (the batch summary stays honest), with `branch`, `pr_url` and a detail `partial: stopped by <reason>; draft PR opened`. A stop with no commits is `failed` with no pull request. When the last session left no bundle of its own (it ran out of memory, was killed, or asked a question) the latest earlier session's bundle is handed over instead. The task's usage that the scheduler sees is held at the task's cap once a session has ended (and within a tenth of it while one winds down), because a cap stop ends a little over the cap and a report past it cancels the task before the handover; a runaway tally further over is still stopped. A verification that cannot run in a partial handover is recorded (`exit_code` -1) and does not stop the push. The task's `result/v1` names the branch and the pull request and says the work is on a partial draft pull request.
- **Per-task limits.** `driven.tasks[].max_turns` (1 to 1000) and `max_minutes` (1 to 480) replace the preset's for that task's sessions. Additive to `request/v1`.
- **Restart.** The task's journal entry (ADR 0043) gains `continuation`, `prior` (the earlier sessions' usage), `runs`, `session_started`, `best` (the bundle to hand over or seed from), and the continuation's prompt and event text; `run_id` and `container` are always the latest session's. The orphan sweep keeps every session's run of a saved task. A continuation whose container never started is started again from the previous session's bundle (read from its output volume if the scratch directory is gone) under a new run id on the same branch. A restart during a continuation re-attaches to that continuation's container, keeps the count and the usage, and continues from there. The task's result record and its handover use the last session's run id (the verifier reads that session's output volume); the result's children include the research and review runs of every session.

## Consequences

Token spend per task can grow up to (1 + `max_continuations`) times a single session's, within the task's token cap, which still binds the sum. A continuation is a second session container for the same task while the first is removed, so the box holds no more containers than before; memory per task is unchanged. A continuation pays again for reading the repository and the diff; the note tells it not to redo research.

The snapshot, the seed fetch and the `commits` field live in the session driver, which is in the session image: the new behaviour needs a new image digest in `driven.images`. With an old image no snapshot is committed and `commits` is 0, so there is no continuation and no partial pull request (today's behaviour).

A continuation sees its predecessor's half-finished work, wrong turns included; it may repair or redo. A partial pull request can hold broken code by design and is a draft that the maintainer reads first. A session that switched to another branch name before it was stopped is not found by the snapshot (it commits to the task branch, or to HEAD when the task branch is missing). A session (first or continuation) that ends `needs_input` after committing is handed over as a partial draft pull request with its questions in the body and in the task detail; the task stays `needs_input`, so the questions still surface. A rate-limited session (ADR 0045's pause) is not handed over by this change.

## Reopen if

Continuations rarely finish what the first session started (then the turn limit, not a second chance, is the thing to tune); partial pull requests pile up unread; spend per task is dominated by repeated reading (then seed the continuation with a summary the first session wrote); a second server shares a runner and `seed.bundle` needs an owner check.
